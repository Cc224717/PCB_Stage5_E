# Stage4 部署环境说明（RTX 3050 Laptop 实测）

本文记录成员 D 在本机完成 INT8 / 剪枝 / 多后端补测时的实际环境与结论，便于复现与交接。

## 1. 硬件与系统

| 项 | 值 |
|---|---|
| OS | Windows 10/11 (build 26200) |
| CPU | Intel Core i5-11400H |
| GPU | NVIDIA GeForce RTX 3050 Laptop GPU（4 GB） |
| 驱动 / CUDA | CUDA 12.4（与 PyTorch cu124 匹配） |
| WSL | Ubuntu（仅用于 LiteRT/TFLite 导出；Windows 不支持） |

工作目录使用 `C:\pcb_stage4` 目录联接指向套件根目录，避免中文路径与长路径问题。

## 2. 软件环境

### 2.1 Windows（主流程：baseline / prune / TensorRT）

- Conda 环境：`pcb-stage4`
- Python：3.11.18
- PyTorch：2.6.0+cu124
- Ultralytics：8.4.212
- TensorRT：10.3（cu12 对应包，勿装 cu13）
- 其它：见 `requirements-stage4.txt`（onnx / onnxruntime-gpu / onnxslim / pandas / pyyaml 等）

安装要点：

```text
conda activate pcb-stage4
pip install -r stage4_deployment/requirements-stage4.txt
# TensorRT 需与 CUDA 12.x 匹配，单独安装 tensorrt==10.3.x（cu12）
```

### 2.2 WSL Ubuntu（LiteRT / TFLite）

- 虚拟环境：建议放在 Linux 本地盘 `~/.venv-tflite`（勿装在 `/mnt/c`，pip 极慢且易占满 `/tmp`）
- 配置：`stage4_deployment/stage4_config_wsl.yaml` + `PCB_YOLO_DATASET/data_wsl.yaml`
- 关键依赖：`litert-torch`、`ai-edge-litert`、`ultralytics`
- `TMPDIR` 请指向磁盘路径（如 `/root/tmp`），避免 tmpfs `/tmp` 空间不足
- 若代理导致 pip 卡住，先关闭系统代理后再装

```bash
wsl -d Ubuntu --cd /mnt/c/pcb_stage4 -e bash -lc \
  "export TMPDIR=/root/tmp; source ~/.venv-tflite/bin/activate && \
   python stage4_deployment/stage4.py \
     --config stage4_deployment/stage4_config_wsl.yaml \
     --model lightweight_baseline --action export --format tflite"
```

## 3. 配置与路径注意

- 主配置：`stage4_deployment/stage4_config.yaml`
  - `device: 0`（使用本机 GPU）
  - 剪枝微调 `batch: 2`（1024 输入下 batch=8 在 4GB 显存易 OOM）
  - 剪枝 `finetune_epochs: 30`
- 数据集：`PCB_YOLO_DATASET/data.yaml` 使用绝对路径 list（`train.txt` / `val.txt`），类别顺序需与训练一致
- engine 与显卡 + TensorRT 版本强绑定，不可跨机直接拷贝；目标机需重新 `export --format engine_*`

## 4. 本机实测结果摘要（RTX 3050）

结果追加写入 `stage4_deployment/outputs/comparison.csv`。

| 方案 | backend / precision | mAP50 | mAP50-95 | FPS | 体积 MB | 备注 |
|---|---|---:|---:|---:|---:|---|
| high_accuracy 原模型 | PyTorch FP32 | 0.927 | 0.505 | ~10.0 | 8.2 | 本机 baseline |
| lightweight_baseline | PyTorch FP32 | 0.913 | 0.495 | ~11.7 | 6.3 | 本机 baseline |
| high_accuracy 剪枝 20% 微调后 | PyTorch FP32 | 0.928 | 0.503 | ~9.9 | 8.2 | ΔmAP50-95 ≈ −0.0015，通过停止规则 |
| high_accuracy TensorRT INT8 | TensorRT INT8 | 0.923 | 0.491 | ~14.7 | 9.3 | ΔmAP50-95 ≈ −0.014，通过；FPS 仍 < 20 |
| lightweight TFLite (WSL CPU) | LiteRT/TFLite FP32 | 0.909 | 0.495 | ~4.2 | 12.3 | 与 PyTorch 精度基本一致；CPU XNNPACK |

停止规则（配置）：

- `max_map5095_drop: 0.02`
- `realtime_fps: 20`
- 导出需与 PyTorch 精度基本一致

结论要点：

1. **剪枝 20% + 30 epoch 微调**：精度几乎不掉，可作为部署候选压缩路径。
2. **TensorRT INT8**：体积约 9.3 MB，精度下降约 0.014（未超 0.02）；本机端到端 FPS≈14.7，未达实时阈值 20（推理核约 6.4 ms，瓶颈在预处理/后处理与 IO）。
3. **TFLite / LiteRT**：仅 Linux/macOS；WSL 导出成功，精度对齐 PyTorch（mAP50-95≈0.495）；本机 CPU 约 4 FPS，适合边缘/移动侧参考，非本机 GPU 实时路径。


## 4.1 RTX 3050 最快方案（GPU 实测，图像预加载）

测速口径：warmup 后对内存中的图像循环 predict（不含反复磁盘读图）。此前把 TensorRT 误跑在 CPU 设备配置上，且每次读盘，FPS 被严重低估。

| 方案 | mAP50 | mAP50-95 | FPS | 延迟 ms | 体积 MB | 推荐 |
|---|---:|---:|---:|---:|---:|---|
| **lightweight TensorRT INT8** | 0.906 | 0.495 | **74.6** | 13.4 | 8.2 | **本机最快** |
| high_accuracy TensorRT INT8 | 0.923 | 0.491 | 69.0 | ~14.5 | 9.3 | 速度次优 |
| lightweight TensorRT FP16 | 0.914 | 0.497 | 66.1 | ~15.1 | 10.2 | 轻量高精度 |
| high_accuracy TensorRT FP16 | 0.928 | 0.506 | 60.1 | 16.7 | 13.8 | **精度最高且仍很快** |

部署建议：
- 要**最快**：rtifacts/lightweight_baseline/engine_int8/best.engine
- 要**精度优先且仍实时**：rtifacts/high_accuracy/engine_fp16/best.engine
- 均远超实时门槛 FPS>20；精度相对原 FP32 掉幅均在停止规则内。
